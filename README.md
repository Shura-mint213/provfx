# 🎓 StudTracker (Система отслеживания траекторий студентов МАИ)

**StudTracker** — это веб-платформа для студентов и администраторов, предназначенная для ведения профилей студентов («стендов»), планирования целей, визуализации личного прогресса и импорта репозиториев проектов из GitHub.

Платформа спроектирована как пошаговый интерактивный конструктор портфолио с поддержкой совместной работы и гибким администрированием.

---

## 🛠 Технологический стек

* **Backend**: Vanilla PHP 8.0+
* **Database**: MySQL (с поддержкой внешних ключей и каскадного удаления)
* **Frontend**: HTML5, Vanilla JavaScript (ES6+), Tailwind CSS, FontAwesome 6 (иконки), Google Fonts (Roboto)
* **Интеграции**: GitHub API (cURL, OAuth 2.0 Flow), парсинг зависимостей проекта (`package.json`, `composer.json`, `requirements.txt` и др.)
* **Безопасность**: Хеширование паролей (bcrypt), шифрование GitHub токенов (AES-256-CBC), защита от CSRF-атак.

---

## 🚀 Основной функционал

### 1. Стенд студента и Галерея
* **Общая галерея**: Публичный список всех опубликованных портфолио («стендов») студентов с возможностью поиска.
* **Стенд (Профиль)**: Визуальная страница с аватаром, академическими данными (кафедра, группа, семестр), SMART-целями, картой прогресса, списком навыков, компетенций и проектов.
* **Система черновиков**: Профиль виден в галерее только после переключения тумблера «Опубликовать».

### 2. Пошаговый конструктор профиля (Wizards)
* **Шаг 1: Кто я**: Настройка аватара, направления, группы, а также добавление хард/софт навыков с указанием уровней владения.
* **Шаг 2: Цель**: Определение SMART-цели, даты дедлайна и перечня критериев успешности её достижения.
* **Шаг 3: Путь (Карта Тэррелла)**: Интерактивная таймлайн-карта для отображения точек прогресса (Достижения, Кризисы, Цели) на координатной сетке.
* **Шаг 4: Компетенции и Проекты**: Управление списком проектов и компетенций, добавление ролей, ссылок на репозитории и участников.
* **Шаг 5: Рефлексия**: Пост-анализ проделанной работы (что сработало, какие были ошибки, что планируется изменить).

### 3. Интеграция с GitHub OAuth и Импорт репозиториев
* **Авторизация через Popup**: Связывание аккаунта с GitHub без перезагрузки основной формы и потери заполненных данных.
* **Шифрование**: GitHub токен хранится в базе данных в зашифрованном виде (алгоритм AES-256-CBC с использованием 32-символьного ключа шифрования).
* **Умный импорт репозиториев**:
  * Получение списка публичных репозиториев пользователя.
  * Сканирование и парсинг файлов конфигурации (`package.json`, `composer.json`, `requirements.txt`, `pom.xml`, `go.mod`, `Cargo.toml`).
  * Автоматическое определение стека технологий (например, React, Laravel, Next.js, Django, Spring Boot и др.) и подстановка его в стек проекта.

### 4. Совместная работа над проектами
* **Добавление участников**: Поиск студентов по логину/зачётке и отправка приглашений в проект.
* **Центр уведомлений**: Интерактивный колокольчик в шапке для принятия или отклонения приглашений в проекты.
* **Кросс-оценки (Peer Review)**: Возможность оценивать участников совместного проекта по 5-балльной шкале с текстовым комментарием.

### 5. Панель администратора
* **Управление ролями**: Изменение ролей пользователей (Обычный пользователь $\leftrightarrow$ Администратор).
* **Панель экспорта данных**:
  * Фильтрация студентов по дате создания, статусу публикации и конкретному ID/зачётке.
  * Выбор экспортируемых сущностей (Студенты, Навыки, Компетенции, Проекты, Участники, Оценки, Чёрные списки и GitHub данные).
  * Поддержка форматов **JSON, XML, CSV, XLSX (Excel)**.
  * Безопасная опциональная выгрузка дешифрованных GitHub токенов с двойным подтверждением согласия администратора.

## 🔒 Система блокировок (5 уровней)

В системе реализован гибкий механизм ограничения взаимодействия между пользователями и блокировки нарушителей администраторами.

| Уровень | Кто ставит | Описание и ограничения |
| :---: | :---: | :--- |
| **Level 0** | — | **Нет блокировки**: Взаимодействие полностью открыто. |
| **Level 1** | Пользователь | **Мягкий Mute**: Блокируемый не может писать сообщения и приглашать в проекты. Разрешен просмотр профиля и добавление в обратную сторону. |
| **Level 2** | Пользователь | **Полный блок**: Блокируемый скрыт из галереи, не видит профиль blocker'а и не может с ним взаимодействовать. |
| **Level 3** | Администратор | **Ограничение действий**: Нарушитель может войти в систему и просматривать стенды, но не может создавать проекты, писать комментарии или отправлять инвайты. |
| **Level 4** | Администратор | **Бан аккаунта**: Полный запрет входа в систему. При попытке авторизации выводится сообщение о блокировке. |

## ⚙️ Настройка и Конфигурация

Все глобальные настройки приложения находятся в файле **`config.php`** в корневой директории:

```php
// Настройки подключения к базе данных MySQL
define('DB_HOST', 'localhost');
define('DB_USER', 'root');
define('DB_PASS', '');
define('DB_NAME', 'host12412319_studtracker');

// URL вашего приложения
define('BASE_URL', 'http://localhost/');

// Настройки интеграции GitHub OAuth
define('GITHUB_CLIENT_ID', 'ваш_client_id');
define('GITHUB_CLIENT_SECRET', 'ваш_client_secret');
define('GITHUB_ENCRYPTION_KEY', '32-символьный_ключ_для_aes_256');
```

> [!IMPORTANT]
> Для корректной работы GitHub OAuth убедитесь, что в панели управления вашим GitHub App в поле **Authorization callback URL** указан адрес:
> `http://localhost/api/auth/github/callback.php` (или домен вашего сайта).

## 📂 Структура проекта

```
├── config.php                # Конфигурационный файл
├── init.php                  # Файл инициализации сессий и БД
├── db/                       # SQL миграции и дампы структуры базы
└── public_html/              # Публичная директория веб-сервера (DocumentRoot)
    ├── form.php              # Главный пошаговый конструктор профиля
    ├── stand.php             # Страница просмотра стенда
    ├── gallery.php           # Страница галереи
    ├── get_avatar.php        # API отдачи аватарок из BLOB
    ├── blacklist.php         # Страница управления Чёрным списком
    ├── admin/                # Панель управления администратора
    │   ├── users.php         # Список пользователей, смена ролей
    │   └── export.php        # Страница и логика гибкого экспорта данных
    └── api/                  # API endpoints
        ├── github_helper.php # Класс шифрования токенов и детекции стека репозиториев
        ├── auth/             # Авторизация GitHub OAuth (url.php, callback.php, disconnect.php)
        └── github/           # GitHub API (repos.php, import.php)
```
